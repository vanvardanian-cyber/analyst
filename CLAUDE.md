# easestore-tools — project memory

## What this is
Seller tooling for **easestore.de** (Amazon.de FBA business, future SaaS product).
Two deliverables live here:
1. **The Niche Funnel** — `tools/seasonality/index.html` (EN) + `tools/seasonality/ru/index.html` (RU).
   A single-file, fully client-side web tool: 4 gates (Seasonality → Competition/Xray →
   Unit economics → Keywords/launch cost). Deployed via Vercel; production URL is the
   tools subdomain of easestore.de. Files users drop NEVER leave the browser — that is
   a core product promise (GDPR positioning). No backend, ever, without an explicit decision.
2. **The workbook** — `workbook/amazon-de-seller-workbook-v4-EN.xlsx`, generated by
   `build/build_v4.py`. The workbook is the source of truth for all formulas and
   thresholds; the web tool mirrors it, never contradicts it.

## Business context (why the numbers look like they do)
- Non-EU seller (Georgian Individual Entrepreneur, 1% turnover tax) on Amazon.de.
- Deemed supplier: 19% German VAT never reaches the seller → net = gross / 1.19.
- Referral fee is charged on the VAT-INCLUSIVE price. Duty on CIF base (EXW + freight).
- Breakeven ACOS = contribution margin ÷ GROSS price (ads console measures VAT-incl sales).
- Budget class: ~€6,500 first product. Every verdict is calibrated for a small-budget
  first launch, not for established operators.

## Hard rules
1. **Single file per page.** All CSS/JS inline. External scripts only from cdnjs
   (currently SheetJS 0.18.5). No build step for the web tool.
2. **Client-side only.** No fetch to any server with user data. localStorage is allowed
   (own domain) for the planned dossier feature.
3. **Thresholds change only when the LOGIC is wrong, never because a result is
   inconvenient.** Every new metric needs a "kill-story" — a real niche it would have
   killed or saved. Every threshold is documented in the page footer, none hidden.
4. **EN is the master, RU is generated.** After ANY change to
   `tools/seasonality/index.html`, update the translation pairs in
   `build/build_ru_page.py` and run it (`python3 build/build_ru_page.py` — check the
   paths at the top; it fails loudly listing untranslated strings). Never hand-edit
   the RU file. Commit both.
5. **Test before delivering.** Headless Chromium via Playwright
   (`npm i playwright`, launch with `executablePath: '/opt/pw-browsers/chromium'` if
   present, else default). Test fixtures = real Helium 10 exports; verify computed
   numbers against an independent Python mirror, not against the page's own output.
6. **Workbook edits** go through `build/build_v4.py` (openpyxl), then MUST run the
   xlsx recalc step so formulas carry computed values. Formulas use legacy names
   (NORMINV/NORMDIST/NORMSDIST, no XLOOKUP/FILTER) for LibreOffice compatibility.
   Inputs = blue font on yellow fill; formulas black; cross-sheet pulls green.
7. Educational tool, not financial advice — keep that line in every footer.

## Current gate logic (summary — read the page source for exact bands)
- Gate 1: monthly averaging of weekly points, seasonal index, amplitude bands
  (1.5/2.5/4), top-4 share, YoY direction (±5%/−15%), year-consistency (mean pairwise
  Pearson of log vectors, 0.4/0.7), seasonal strength (Hyndman F_s, needs 30+ months).
- Gate 2: dedupe ASINs (sponsored repeats), drop off-modal-category rows. Checks:
  top-10 revenue ≥€40k, top-ASIN share <30/40%, review moat (>500-review count with
  proof-of-entry softening: ≥3 listings ≤100 reviews earning >€3k/mo → yellow; seller
  age ≤18 months reported as "new shop" composition), Amazon dominant (≥10% rev or
  top-10 earner = hard red; present = price-anchor yellow), CN+HK 40/60%, fresh
  entrants (with >€20k instant-revenue relaunch warning), weak competitor ≤4.3★,
  price corridor €20–70, median weight 2/4 kg.
- Gate 3: Sheet 3 math live; margin ≥35% green, 30–35 yellow, <30 red; max-EXW ceiling.
- Gate 4: searches-per-sale (20/60/120 bands), trend ≥+200% fad flag, CPR push cost =
  CPR×(landed+discount)+8×daily ads (landed auto-fills from Gate 3), CPR-vs-organic
  velocity warning (>3×), title density ≤5 opening / ≥30 saturated, P10/P90 suggestion
  (4%/15% of summed keyword sales × months). Green requires a strong-intent affordable
  keyword, not merely an affordable one.

## Conventions
- dataviz palette (already in the page CSS vars): series-1 #2a78d6, status good
  #0ca30c / warning #fab219 / critical #d03b3b; dark mode via prefers-color-scheme.
- Verdict tone: honest, specific, never salesy. Yellow = "here is the risk you are
  accepting", red = "recommended: change niche" but NEVER hard-block navigation.
- Commit style: one feature per commit, message explains the WHY.
